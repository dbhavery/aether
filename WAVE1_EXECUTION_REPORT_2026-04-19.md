## 2. Workspace design actually implemented

Two workspaces coexist in the same repo:

### 2.1 Rust workspace (Cargo)

- Root `Cargo.toml` declares members for the four Rust shared-infra crates:
  `packages/event-bus`, `packages/storage`, `packages/media-engine`, `packages/telemetry`.
- Each member inherits `edition`, `rust-version`, `license`, `repository`, `authors` from `[workspace.package]`.
- Shared dependency versions pinned in `[workspace.dependencies]`: `thiserror`, `tokio`, `serde`, `serde_json`, `tracing`.
- Release profile tuned (`lto="thin"`, `codegen-units=1`).
- Toolchain pinned to `stable` with `rustfmt` + `clippy` via `rust-toolchain.toml`.

### 2.2 TS / pnpm workspace

- Root `package.json` private, declares `packageManager: pnpm@9.12.0`, engine node ≥ 20.10.
- `pnpm-workspace.yaml` enumerates Wave 1 TS packages (`packages/types`, `packages/ui-kit`) and has commented placeholders for future layer facades and apps.
- All TS packages extend `tsconfig.base.json` (ES2022 target, bundler resolution, strict + exact optional property types + no unchecked indexed access).
- Root scripts (`build`, `typecheck`, `lint`, `test`) all use `pnpm -r --if-present` so additions come online automatically.

### 2.3 Legacy Python coexistence

- Legacy Python artifacts (`pyproject.toml`, `requirements*.txt`, `src/`, `tests/`, `configs/`, `data/`, `desktop/`, `frontend/`, `scripts/`, `.venv/`) remain in place, untouched, and are not members of either workspace.
- They are **not** under Rust or TS CI once CI lands. They will be ported capability-by-capability in Waves 2–4 (X2 / X4) and retired only after parity.

### 2.4 Package kind choices

| Package | Kind | Rationale |
|---|---|---|
| `event-bus` | Rust crate | Event surface is canonical in Rust; TS mirrors are generated. |
| `storage` | Rust crate | SQLite driver + audit-chain primitives are latency/safety-critical. |
| `media-engine` | Rust crate | STT/TTS/VAD control plane is Rust (chunk timing, viseme sync); borrowed inference models wrap behind traits. |
| `telemetry` | Rust crate | `tracing` subscribers are Rust; OTLP export is Rust. |
| `types` | TS package | Destination for generated TS bindings; consumed only by TS. |
| `ui-kit` | TS package | Design tokens + future React primitives. |

Documented in `packages/*/README.md` files.
