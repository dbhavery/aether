Aether v0.1.0 · oss preview

A local-first AI companion, built around one invariant.

Every action Aether takes clears a non-bypassable policy gate before it touches the world. No exceptions, no fast paths, no admin mode. The gate is the ground floor; everything else grows on top.

Why

Most AI assistants assume the language model is the product. Aether doesn’t. The model is a service. The relationship — memory, presence, trust, timing — is the product, and policy is what keeps the relationship intact over years of use.

That means a companion you can still trust when half the system is broken. A persona you can swap without rewriting history. An audit trail you can read in five years without vendor lock-in. A local model by default, with remote calls as a deliberate escalation.

Seven layers, one gate

Aether is organized into seven independent engines. Every side-effectful call routes through L5, the policy engine. Sibling engines do not import each other — a CI-enforced linter refuses the edge.

Try it

Preview-grade. Not a product. One command and a tiny CLI that walks a real turn through L5 and into a router adapter. 

$ git clone https://github.com/dbhavery/aether.git
$ cd aether
$ cargo run -p aether-l1-cli

Aether L1 demo — community preview.
persona     : aurora (v1, preferred tier local-full)

aether> read /tmp/x
  final-state  : Completed
  policy       : Allow   (grant=g-1, audit=a-1)
  route        : tier=local-full  provider=reflex-stub

aether> shell ls
  final-state  : PolicyDenied
  policy       : Deny    (ModeDeny, audit=a-2)

aether> delete /tmp/y
  final-state  : AwaitingPolicyApproval
  policy       : Ask     (ticket=t-1, audit=a-3)

Every field in that output is produced by real engine code. The audit id comes from write_audit. The grant id comes from issue_and_emit_grant. The state trace is the path the turn FSM actually walked.

What’s inside

Shipped in v0.1.0

  • L5 policy engine: 5-stage evaluator, typed decisions allow · ask · draft-only · deny · needs-upgrade
  • Sealed audit log: SHA-256 chain + HMAC-SHA256 per row tampering → named error on verify_chain
  • Durable L5: SqliteGrantLedger, SqliteAuditStore feature-gated, survives process restart
  • L1 turn FSM, first vertical slice idle → policy → route → completed
  • L6 persona compiler, deterministic profile → 7 typed artifacts, no LLM calls
  • Layer-boundary linter, CI-blocking no sibling-engine imports, ever

Not yet

  • Real LLM calls router adapter ships as a stub; provider integrations next
  • Persistent cross-session memory L2 memory kernel is a trait surface so far
  • Desktop shell apps/desktop/ is empty on purpose
  • STT / TTS / avatar pipeline L1 accepts text utterances today
  • OS-keyring for audit key preview stores a 32-byte file next to the DB
  • Approval UX Ask tickets emit but don’t yet render

The roadmap names the next six sessions: memory, approvals, presence, a real provider, persona-driven policy, and a Tauri shell. After that it starts to feel like a companion.
